# Автоматизация существующего Rust-сценария

Agent discovery: GET /api/agent/v1/capabilities. See [HTTP API](agent-api.md) and [montage recipes](montage-recipes.md) for ordered Creative clips across videos. These use the existing Rust routes, not MCP.

Этот документ описывает использование действующей Studio. Прежний Python CLI и предложенные команды create/analyze/events/render не являются доступным интерфейсом этой ветки. Разработка нового CLI не входит в обычную задачу монтажа.

## Выбор пути

Для готового CPU-анализа используй проектный монтаж. Для новых исходников Quick Reel выполняет свежий анализ и требует музыку; при выборе спортсмена или независимой целевой длительности используй проект и последующий персональный монтаж. Маршруты и владельцы перечислены в [current-runtime.md](current-runtime.md).

При HTTP-автоматизации используй действующий локальный сервер и его реальные схемы, соблюдая same-origin проверки. Не добавляй сервер, Python-оркестратор или самостоятельную логику выбора событий вместо Rust-владельца. Если UI-автоматизация или разрешённый HTTP-доступ недоступны, сообщи конкретный недостающий доступ, не выдумывай запасную команду.

## Источники и повторный монтаж

1. Найди реальные project_id, player_id и CPU rally_run_ids. Не перебирай большие покадровые файлы, если достаточно компактного API-индекса.
2. Сверь исходник и версию анализа. Изменение музыки/кадрирования проектного монтажа не требует нового GPU-инференса; смена модели, разрешения анализа или исходного диапазона может потребовать его.
3. Выполни preview. Сохрани project_id, source_fingerprint, число выбранных фрагментов и существенные флаги происхождения/неопределённости.
4. Для start передай expected_source_fingerprint актуального превью. При конфликте источников обнови превью; не повторяй бесконечно start с прежней ревизией.
5. Следи за идентификатором своего задания. При failed, cancelled или interrupted заверши ожидание и сообщи причину. Не останавливай чужие задания.
6. Возвращай подтверждённый сервером media URL или локальный выходной файл и фактические параметры после проверки.

Сохраняй исходники и неизменяемые evidence. Незавершённый результат не считается кэшем. Схемы данных и пути хранения определяют Rust-модули и манифесты; не создавай параллельные events.json/edit_plan.json только ради старого текста skill.

## Возможности и требования

Профили действующего монтажного интерфейса — favorites, player, attacks, report, creative. Названия classic/dynamic/cinematic, универсальный --resume, чисто звуковой кешированный ремикс, библиотека VFX и полный автоматический QC эффектов не являются контрактом существующего API.

При отдельно запрошенном расширении сначала установи владельца по [карте](../../../../docs/RUST_CANONICAL_OWNERS.json) и согласуй новый контракт. Требования к координатам и времени будущих эффектов находятся в [events-editing-vfx.md](events-editing-vfx.md). Обычный монтаж и исправление skill не разрешают автоматически такую разработку.
