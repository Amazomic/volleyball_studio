# Игровые события, монтаж и будущие VFX

## Существующая граница

Rust сохраняет неизменяемые GPU-наблюдения, версионированную CPU-интерпретацию и отдельные решения о личности/действиях. Монтаж использует исходное видео и проверяет связанные источники. Реальные API перечислены в [current-runtime.md](current-runtime.md); владельцы — в [карте](../../../../docs/RUST_CANONICAL_OWNERS.json).

Тип действия из автоматического анализа является гипотезой. Различай проверку происхождения контакта, ручную правку действия и ручное подтверждение личности. Флаг action_classification_verified=false не становится true от выбора фильтра attack. Номер Track ID не заменяет глобальный player_id.

Текущий монтажный API не реализует огонь/шлейф, библиотеку эффектов, произвольный speed ramp или пользовательские подписи. Не передавай выдуманные поля и не называй монтажную библиотеку библиотекой VFX. Запрос эффекта требует отдельного определения объёма работ; это не разрешение незаметно переписать конвейер.

## Требования при отдельно согласованной реализации эффектов

Следующие пункты — требования к будущему расширению, а не описание существующих файлов, API или тестов.

- Сохранять привязку к точному SHA исходника, версии CPU, событию и траектории. Не объявлять отдельные analysis/events.json или editing/vfx_plan.json обязательным существующим форматом: новый формат сначала согласуется с Rust-владельцем.
- Использовать исходное время, FPS/PTS и явно заданное пространство координат. Различать кадр анализа и кадр VFR-оригинала. Одна карта времени применяется к видео, игровым событиям, эффектам и звуку.
- Для участка постоянной скорости v: timeline_time = timeline_start + (source_time - source_start) / v. Для изменения скорости нужна кусочная карта с фактическим округлением к выходным кадрам.
- Для crop/scale: x_out = (x_source - crop_x) * scale_x, аналогично y. Динамические crop/zoom вычисляются для каждого выходного кадра. Фиксированная точка экрана не заменяет траекторию мяча.
- Огонь начинается только после обоснованного контакта нужного типа, не по одной скорости. Шлейф направлен против скорости мяча. При утрате достоверной траектории эффект прекращается; интерполяция имеет явный предел и маркировку.
- Bbox-guard может подавлять сомнительный эффект, но не является маской сегментации. Художественная длительность не продлевает недостоверную траекторию.
- Сохранять пользовательский контроль подписей, внешнего вида и звука. Перед сохранением нового эффекта в будущую библиотеку получить согласие на конкретный предпросмотр; до реализации библиотеки не обещать сохранение.

## Проверка будущего расширения

Нужен детерминированный синтетический пример с известными координатами мяча, временем удара, crop/scale/zoom, замедлением, коротким пропуском и длинным разрывом. Ожидаемые координаты и тайминги вычисляются независимо от реализации рендера.

Например, при source 1920×1080, crop (600, 0, 608, 1080), output 608×1080 точка (900, 400) без zoom должна стать (300, 400); контакт через 0,2 секунды на участке скорости 0,5× появляется через 0,4 секунды на монтажной шкале.

Проверять численную ошибку якоря в отрендеренном изображении, отсутствие огня до удара и после длинного разрыва, направление шлейфа и синхронность звукового акцента. Намеренно смещённый эффект должен проваливать проверку. Проверка JSON-плана не доказывает корректность композитинга; успешное декодирование MP4 не доказывает семантическую точность событий.
