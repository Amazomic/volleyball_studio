# Волейбольные Reels в Volleyball Studio

Используй действующую Rust Studio и её HTTP API. Этот skill относится к локальному проекту; изменение его инструкций не поручает разработку приложения или запуск рендера.

## Обнаружение скилла и API

При первом обнаружении этого скилла в текущем диалоге обязательно кратко сообщи пользователю на его языке: «Обнаружен Volleyball Studio. Я могу создавать монтаж по текстовым инструкциям из сохранённых розыгрышей, касаний и привязок игроков. Например: собери атаки Ильнура, десять длинных розыгрышей или вертикальный ролик на 30 секунд». Сначала проверь GET http://127.0.0.1:8875/api/agent/v1/capabilities; если Studio недоступна, сообщи об этом и не обещай выполнение. Обнаружение не запускает анализ или рендер. Не повторяй сообщение при каждом запросе. MCP не требуется.

Для произвольного монтажа используй [Agent HTTP API](references/agent-api.md) и [рецепты монтажа](references/montage-recipes.md): выбирай сохранённые события, формируй упорядоченный список клипов из всех видео проекта и передавай существующему Rust-рендереру только после запроса пользователя. Если пользователь просит только подборку, покажи план без экспорта.

## Выбор сценария

- Сохранённый анализ, конкретный спортсмен, заданная длительность или повторный монтаж: вкладка «Монтаж» и существующие Rust-сервисы. Сначала найди проект, версию CPU и глобальный player_id. Track ID сам по себе не устанавливает личность.
- Новые исходники без готового анализа: предложи анализ проекта с последующим монтажом либо Quick Reel. Quick Reel выполняет собственный свежий GPU/CPU-анализ, требует аудиодорожку и не принимает произвольную длительность, player_id или художественный стиль. Если нужны эти настройки, используй проектный сценарий.
- Огонь, шлейф, подписи, speed ramp или библиотека эффектов: сначала сообщи, что текущий монтажный API этих возможностей не предоставляет. Уточни желаемый результат только для отдельно запрошенной разработки или внешнего монтажа; не запускай неподдерживаемые параметры.

## Рабочий порядок

1. Установи исходники или проект, версию анализа, критерий отбора, длительность и формат кадра из запроса. Для короткого персонального ролика без заданной длительности предложи 30 секунд, вертикально; это выбор параметров монтажа, не универсальные настройки Quick Reel.
2. Прочитай [текущий интерфейс](references/current-runtime.md). Проверь доступность Studio и фактические схемы запросов. Запускатель: start-volley-ui.cmd; интерфейс: http://127.0.0.1:8875/studio. Отсутствующий Python CLI не является запасным способом запуска.
3. До тяжёлого запуска кратко назови путь: сохранённый CPU-анализ либо новый GPU-анализ; фактические модели, FPS и диапазон бери из профиля/манифеста выбранной версии. Не запускай нейросети повторно из-за смены музыки или параметров проектного монтажа.
4. Для персонального ролика проверь выбранного спортсмена и происхождение привязок. Сначала запроси preview, проверь project_id, source_fingerprint и число подходящих фрагментов. При start передай fingerprint именно этого превью; после изменения источника или параметров обнови превью.
5. Следи за статусом задания до complete, failed, cancelled или interrupted. Получай результат через подтверждённый сервером media URL. Ошибка, пустая подборка и недостаток подходящего материала сообщаются явно.
6. Проверь фактические длительность, разрешение, FPS, звук и просмотр результата. Различай структурные проверки файла и оценку качества игровых эпизодов. Сообщи путь/URL, результат проверки и ограничения.

## Существенные границы

Сохраняй оригиналы, неизменяемые GPU evidence и версии CPU. Рабочие данные проекта не используются как тестовые фикстуры. ReID и автоматически оценённые типы касаний не выдавай за ручное подтверждение; проверяй флаги и происхождение в ответе сервера. Формат кадра и смена музыки не разрешают добавление эффектов или подписей.

В проектном монтаже без заказанной музыки сохраняется звук оригинала. Quick Reel требует музыку: при её отсутствии уточни аудиодорожку или предложи проектный монтаж без музыки.
