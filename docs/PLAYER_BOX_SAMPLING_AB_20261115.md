# Проверка частоты RF-DETR и интерполяции рамок — 2026-11-15

## Задача

Сравнить на одном 10-секундном отрезке измерения рамок RF-DETR Medium каждый 1, 2, 5 и 10-й кадр. Между двумя реальными обнаружениями восстанавливать прямолинейное движение рамки. Не менять действующую частоту GPU-конвейера до проверки качества.

## Метод

- Источник: `examples/gtu_20250316_002.mp4`, временной диапазон 10–20 с.
- SHA-256 исходника: `d92c2e1b3014efd51c62e917488366d8804b225ed4aaad77c025d5af914f7a80`.
- Извлечение: `ffmpeg -ss 10 -t 10 -i INPUT -vf fps=30,scale=640:360 -pix_fmt rgb24 -f rawvideo OUTPUT`. Получился 301 кадр, включая граничный кадр.
- SHA-256 кадров: `357eae8d4b7d0ea11700f0ca67a35e9de955634f6a7b35bd5880ad8ba2b7b67d`.
- Аппаратная платформа: NVIDIA GeForce RTX 5070 Ti Laptop GPU; ONNX Runtime CUDA; один процесс по очереди, 8 потоков CPU; RF-DETR Medium, одинаковый ONNX-файл для всех режимов.
- Область измерения: только обнаружение рамок; **не** RTMPose, VBallNet, GPU fusion, CPU tracking/Touch.
- Детекции каждого кадра — опорный результат **той же нейросети**, а не ручная разметка. Проверяется совпадение с ним, а не точность определения людей в реальном мире.
- Промежуточные рамки восстанавливаются только между попарно согласованными наблюдениями; консервативные ограничения на форму, перемещение, перекрытие, неоднозначность заимствованы из `rust/volley-app/src/pose_inference/box_interpolation.rs`. Дубликаты на одном кадре убираются при IoU >= 0.60, как в существующей реализации; Python-оценщик — отдельная проверка алгоритма, а не полный вызов CPU/GPU-пайплайна.
- Для времени выполнено 3 прогона; результаты после загрузки модели. Для качества сравниваются **только промежуточные кадры**, на которых выбранная частота не запускает RF-DETR; попадание — совпадение рамки с детекцией каждого кадра при IoU >= 0.50.

## Качество линейной интерполяции

| Шаг | Покрытие рамок плотного RF-DETR на промежуточных кадрах | Доля восстановленных рамок с IoU >= 0.5 | 95-й перцентиль смещения центров совпавших рамок |
| --- | ---: | ---: | ---: |
| 1 | 100% (эталон самого RF-DETR) | 100% | 0 пикс. |
| 2 | **64.53%** | 94.20% | 1.28 пикс. |
| 5 | **61.11%** | 92.53% | 2.01 пикс. |
| 10 | **57.31%** | 85.55% | 2.66 пикс. |

Покрытие не означает recall по людям: опорные рамки могут включать ошибочные обнаружения. Высокий IoU совпавших рамок не отменяет недостающие предсказания. Главная потеря в этом эксперименте — отказ интерполяции от неоднозначных пар, а не большие координатные ошибки успешно восстановленных рамок. На шаге 2 пропускается 598 из 1686 рамок плотного референса на промежуточных кадрах; на шаге 10 — 1296 из 3036.

## Вывод

На данном коротком фрагменте полная детекция RF-DETR каждого кадра технически выполнима быстрее реального времени, а редкая детекция с текущими консервативными правилами интерполяции существенно сокращает доступные рамки относительно плотного RF-DETR. Простой переход на более редкую детекцию нельзя считать улучшением качества.

Перед изменением умолчаний отдельно проверить полный GPU-проход (RF-DETR + RTMPose + VBallNet), CPU Track ID и ошибки привязки на касаниях. Частоту поз можно оставить независимо выбранной. Производственные настройки, данные проектов и запущенная Studio этим тестом не менялись.
