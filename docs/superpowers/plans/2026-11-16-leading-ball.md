# Сопровождение ведущего мяча — план реализации

**Цель:** исключать далёкие детекции во время потери единственного игрового мяча, сохранять его идентификатор и интерполировать только принятую траекторию.

**Архитектура:** владелец геометрии — `volley-core/src/touch_pipeline/ball_continuity`; общий адаптер чтения CPU replay — `volley-app/src/cpu_retrack/ball_track.rs`. Детерминированный последовательный проход хранит ведущий мяч независимо от страниц предпросмотра и блоков CPU. GPU evidence и существующие результаты не изменяются.

**Стек:** Rust, существующие JSONL replay, Axum, текущая баллистическая интерполяция.

**Спецификация:** `docs/LEADING_BALL_TRACKING.md`, запрос пользователя от 2026-11-16.

## Ограничения

- Одна реализация правил в Rust; без комментариев в коде.
- Исходные GPU/CPU snapshots, видео, ручные связи и активные задания сохраняются.
- Первичные данные содержат максимум один VBallNet-кандидат на кадр; число кандидатов не равно истинному числу мячей в сцене.
- Синтетические точки служат только предпросмотру, не доказательством Touch.
- Чужие незакоммиченные изменения не включать в коммит.

## Основные риски для проверки

- Дрожащая ложная точка справа после ухода мяча за верх кадра, включая кадры 388–399.
- Резкое реальное изменение скорости после контакта и возвращение из-за границы кадра.
- Длинный пропуск без переключения; новый выбор только после явного начала следующего розыгрыша; начальное подтверждение по трём согласованным наблюдениям.
- Начало страницы/CPU-блока внутри ложного фрагмента.
- Перепутанные SHA, изменение файла и ошибочные/нечисловые координаты.
