# GPU по умолчанию в Volleyball Studio

Проверка 2026-11-17, база 9880b9e, ветка codex/gpu-defaults.

| Этап | Выбор по умолчанию | Ограничения |
| --- | --- | --- |
| VBallNet, RF-DETR Medium, RTMPose | CUDA, без неявной замены модельной сессии на CPU | Неподдерживаемые CUDA-операции и обработка тензоров требуют отдельного профилирования |
| Основной stride=9 / photo конвейер | Один общий декодер, NVDEC после preflight | HDR, 10-bit и неподтверждённые форматы сохраняют software fallback |
| Quick Reel, отдельные модели, video-pose, диагностические окна | Тот же выбор NVDEC и поворот после hwdownload | На WSL используется общая сертификация формата, перед выдачей кадров; в середине потока смены backend нет |
| Подготовка видео | NVENC CQ17, автоматический аппаратный декодер FFmpeg | При отказе попытка закрывается и удаляется partial, затем CPU CRF20; отмена не запускает повторную попытку |
| Монтаж, в том числе фрагменты короче 7 секунд | Auto сначала NVENC | Явный CPU сохраняется; неподдерживаемый размер/отказ кодировщика переводит попытку на CPU |
| Титр статистики | Тот же выбор кодировщика Auto/GPU/CPU | Рисование текста остаётся CPU-фильтром |
| Склейка совместимых фрагментов, добавление музыки | Копирование видеопотока | Без повторного кодирования и потери качества |
| Трекинг, Touch, розыгрыши, статистика | Rust CPU replay | Это существующие геометрические алгоритмы; GPU-реализации отсутствуют |
| fps/scale/format/crop, подготовка тензоров | Существующие CPU-фильтры/преобразования | Перенос на CUDA требует отдельного доказательства пиксельной и модельной эквивалентности |

Лимит GPU-памяти профиля по умолчанию равен 0, то есть приложение не задаёт искусственный предел arena. Значение не означает резервирование всей VRAM. Сохранённые явные настройки пользователя не заменяются. Нагрузка GPU зависит от этапа, данных, CPU-преобразований, передачи памяти и ожидания ввода; предпочтение GPU не гарантирует 100% загрузки.

Новые пути используют существующие владельцы: raw_decoder/shared, preparation и montage. Схемы кэшей, подтверждённые личности, исходные видео и готовые анализы не переписываются. Ранее подготовленные SHA-проверенные кэши можно повторно использовать независимо от кодировщика; GPU по умолчанию применяется при новой подготовке.

Проверки: регрессии сначала показали libx264 вместо NVENC в подготовке и CPU для Auto-клипа 0.1 секунды. После исправления полный Rust-набор, cargo check, fmt, WASM, ownership и roadmap проходят. Отдельно на RTX 5070 Ti Laptop GPU / FFmpeg 7.1.1 пройдены принудительные NVDEC-тесты H.264 320×180 и HEVC 3840×2160, 0/−90/+90/180°, с побайтным сравнением обоих модельных форматов в общем и отдельных декодерах. Реальная подготовка через NVENC сохраняет оригинал, 30 FPS и SHA-receipt; реальный GPU-экспорт сохраняет размер/FPS и валидный вертикальный MP4. Для слишком малого NVENC-размера 2×2 подтверждён CPU retry с проверенным кэшем. Полный набор проверяет отмену и очистку partial. Первый GPU-export тест получил аппаратный отказ на 102×180; тест допустимого GPU-экспорта использует исходник 640×360, а неподдерживаемые размеры проверены отдельно через резервный путь.

Не измерены: ускорение полного реального матча, реальная доля CPU-операций внутри ONNX-графов, независимая игровая точность, пиковые RAM/VRAM. Новые незакоммиченные функции другого активного исполнителя, включая фрагментный браузерный playback, не входят в снимок этой проверки и не редактировались.

Документация: [FFmpeg hardware acceleration](https://ffmpeg.org/ffmpeg.html#Advanced-Video-options), [NVIDIA FFmpeg guide](https://docs.nvidia.com/video-technologies/video-codec-sdk/13.1/ffmpeg-with-nvidia-gpu/index.html), [ONNX Runtime CUDA EP](https://onnxruntime.ai/docs/execution-providers/CUDA-ExecutionProvider.html).
