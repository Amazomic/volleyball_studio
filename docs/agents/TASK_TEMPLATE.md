# Шаблон карточки параллельной задачи

Скопировать в `docs/agent-runs/<run-id>/tasks/<task-id>.md`. Карточка принадлежит одному исполнителю; права подтверждает координатор в актуальном реестре по [регламенту](../AGENT_PARALLEL_WORKFLOW.md). После копирования заменить ссылки на рабочие пути. Снимок назначения в этой карточке не заменяет актуальный реестр.

## Назначение

- Run ID / Task ID: `<значения>`
- Исполнитель / координатор: `<идентификаторы>`
- Grant epoch и подтверждение: `<значения>`
- Base SHA: `<полный-SHA>`
- Абсолютный worktree / ветка: `<путь> / codex/<run-id>/<task-id>`
- Абсолютный путь актуального реестра: `<путь>`
- Цель и воспроизводимый сценарий: `<до/после>`
- Зависимости `depends_on`: `<task-id и интегрированные-SHA либо нет>`

## Разрешённая область

- `write_paths`: `<точные-пути-кода-тестов-и-этой-карточки>`
- `read_paths`: `<владельцы-схемы-вызывающие-модули-тесты>`
- `contracts_read`: `<имя/версия/семантика>`
- `contracts_write`: `<согласованное-изменение либо нет>`
- Создаваемые/переименовываемые/генерируемые файлы: `<пути либо нет>`
- Общие файлы, которые должен подключить интегратор: `<список-и-точное-требование либо нет>`
- DataRoot / temp / target / тестовый порт: `<назначенные-значения>`
- Ресурсы по фазам: `<GPU/CPU/RAM и условия выдачи>`

## Проверка

- Критерий приёмки: `<наблюдаемое-поведение-и-метрики>`
- Исходные сбои: `<команды, результаты, base-SHA>`

## Передача результата

- Текущий статус и подтверждённый grant epoch: `<значения>`
- Коммиты к интеграции по порядку: `<полные-SHA>`
- Проверенный SHA кода: `<SHA>`
- Фактические изменённые пути: `<список>`
- Команды, коды завершения и артефакты проверок: `<результаты>`
- Изменение качества/скорости: `<измерения либо NOT MEASURED>`
- Изменение контрактов/кэшей и действия интегратора: `<описание либо нет>`
- Ограничения и непроведённые проверки: `<список>`
- Запись для переноса в `RUST_MIGRATION.md`: `<короткий-проверяемый-итог>`
- Блокер или следующий шаг: `<действие>`

При первом коммите с результатом можно указать «проверен подготовленный diff поверх `<base_sha>`», если собственный SHA ещё не существует. После коммита передать SHA координатору и записать его следующим изменением карточки; не подменять проверенный SHA текущим HEAD после новых правок кода. Каждый проверенный рабочий инкремент сопровождается записью в этой карточке; общий журнал дополняет интегратор.
