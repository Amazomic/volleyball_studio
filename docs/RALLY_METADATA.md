# Метаданные розыгрыша

В первичном пайплайне метаданные заполняются по ходу анализа и сохраняются в поле `metadata` существующей записи розыгрыша в `projects/<project_id>/native_cpu_rallies/<rally_run_id>/rally_candidates.jsonl`. Для старых результатов предпросмотр вычисляет доступные метаданные при чтении, без изменения сохранённого анализа, при совпадении ревизии калибровки площадки.

## Структура

```json
{
  "rally_id": "candidate-id",
  "start_frame": 300,
  "end_frame": 540,
  "team_1": [10, 11],
  "team_2": [20, 21],
  "touches": [
    {"track_id": 10, "kind": "serve", "time_sec": 10.33},
    {"track_id": 20, "kind": "dig", "time_sec": 12.33},
    {"track_id": 21, "kind": "attack", "time_sec": 15.33}
  ],
  "winning_team": "team_2"
}
```

- `rally_id` — ID розыгрыша.
- `start_frame`, `end_frame` — границы розыгрыша в кадрах.
- `team_1`, `team_2` — уникальные устойчивые Track ID игроков каждой команды в пределах розыгрыша. Количество игроков вычисляется по длинам списков; отдельные счётчик и список не сохраняются. Один ID не может входить в обе команды.
- `touches` — касания в хронологическом порядке: Track ID, тип касания и время в секундах по временной шкале видео. Подача — первое игровое касание с типом `serve`; отдельного поля подачи нет.
- `winning_team` — `team_1` или `team_2`, заработавшая очко. Пока команда не определена — `null`.

## Заполнение

1. После определения границ заполняются rally_id, start_frame и end_frame.
2. После объединения треков и определения принадлежности заполняются составы двух команд.
3. После детекции и классификации касаний заполняется `touches`, включая подачу.
4. После определения результата розыгрыша заполняется `winning_team`.

Никаких дополнительных полей в `metadata`. ID и границы берутся из существующей записи розыгрыша. Не выдумывать неизвестные ID, касания или результат.

Владелец формирования и сохранения — [cpu_rallies.rs](../rust/volley-app/src/cpu_rallies.rs). Правила — [rally_reconstruction.rs](../rust/volley-core/src/rally_reconstruction.rs), [rally_contact_context.rs](../rust/volley-core/src/rally_contact_context.rs). Предпросмотр, отчёт и монтаж используют сохранённые данные.

## Определение подающего

После подтверждения начала подачи и стороны по стабилизированной траектории мяча (calibrated_flight_origin_v6) для дальней команды выбирается устойчивый Track ID, чья опорная точка (середина нижней границы рамки) находится дальше всего от сетки вдоль продольной оси площадки. Используется существующая калиброванная гомография и медиана x_m за первые пять кадров от начала подачи, а не вертикальная координата изображения. Учитываются только наблюдаемые рамки дальней половины в допустимой игровой зоне и согласованная сторона трека. Подтверждение RTMPose не обязательно. При неоднозначном положении сохраняются прежние проверки контакта по позе и входа игрока. Для ближней команды сохраняется существующая проверка удара по позе либо устойчивого входа игрока с края кадра после подачи. Геометрия требует корректной разметки и не гарантирует выбор при отсутствующем треке, одинаковой глубине или ошибке проекции ног прыгающего игрока. Без достоверной стороны или наблюдаемого трека нельзя гарантировать ID: результат остаётся предварительным. Новая версия действует при пересчёте анализа; сохранённые результаты не перезаписываются автоматически.

## Результат розыгрыша

Команда 1 — ближняя сторона сетки (синий цвет), команда 2 — дальняя сторона (красный). Состав определяется на протяжении розыгрыша по существующему голосованию сторон, только для устойчивых Track ID. Неопределённые стороны не назначаются принудительно. Имена в карточке подставляются из текущих привязок ReID/ручных привязок, иначе отображается Track ID.

Отдельный модуль [rally_score.rs](../rust/volley-core/src/rally_score.rs) применяет правила начисления очков. Источники: [официальные правила пляжного волейбола FIVB 2025–2028](https://www.fivb.com/beach-volleyball/the-game/official-rules-of-the-games/) (6, 8, 9, 10, 12, 14), [правила классического волейбола](https://www.fivb.com/volleyball/the-game/official-volleyball-rules/).

- Завершённый розыгрыш приносит ровно одно очко победителю независимо от того, кто подавал; победитель получает право следующей подачи. При переигровке очко не начисляется.
- Первое подтверждённое падение в площадку приносит очко противоположной стороне независимо от распознанных касаний и состава команды. Линия входит в площадку. При ауте очко получает сторона, противоположная последнему достоверному касанию мяча; неизвестное последнее касание нельзя заменять более ранним.
- Само касание мячом сетки не является ошибкой. Если после приёма мяч падает на своей половине, очко получает соперник; если мяч пересекает сетку, игра продолжается. Спасение мяча из сетки возможно в пределах разрешённых командных касаний.
- Не более трёх командных касаний до возвращения мяча; в пляжном волейболе блок входит в эти три, в классическом — нет. Четвёртое касание, двойное касание, заступ, касание сетки игроком и другие нарушения должны опираться на достоверные наблюдения и применимые правила формата. Автоматическое судейство этих ошибок пока не реализовано, пропущенные детектором касания не позволяют объявлять нарушение.
- Сторона площадки не является постоянной идентичностью команды: при смене сторон и монтаже видео нельзя выводить победителя предыдущего розыгрыша только из положения следующего подающего.

При пограничном событии line_uncertain исходная метка сохраняется, а известная половина используется как предварительная оценка. Если центр мяча расположен до 0,15 номинального метра от проекции сетки, учитывается высота центра мяча при касании пола (радиус 0,105 м; текущая модель камеры использует номинальную площадку 18×9 м и высоту сетки 2,43 м). Поправка допустима только при согласованной калибровке сетки, совпадении позиции события с проверенным наблюдением мяча того же кадра и одинаковой однозначной половине для обеих скорректированных позиций внутри площадки. Это геометрическая гипотеза, не судейское подтверждение. Отсутствие падения, неразличимая сторона или неизвестное последнее касание при ауте сохраняют winning_team=null. Для сохранённых результатов с той же ревизией площадки карточка пересчитывает доступный результат, не изменяя архив и не добавляя вымышленных касаний. Последующие отскоки не начисляют новых очков.
