# Привязки игроков на склейке ролика

Проверка 2026-11-16, база `b2b6ce6`, ветка `rust`.

## Причина

В проекте `d6451abac405` на границе кадров 850–855 исчезают три устойчивых трека (1, 2, 7), появляются два (11, 12), а геометрически подходящие ID 4 и 6 продолжаются на других людях. Пользователь подтвердил, что исходник склеен из разных эпизодов.

Детектор смены состава требовал минимум три исчезнувших и три новых устойчивых трека. Граница не распознавалась. Фотоавтопривязка выбирала одно имя для всего длинного ID: 4 → Раиля, 6 → Ирек. На кадре 940 ID 6 уже описывал Влада во время передачи; ID 4 описывал Ирека.

## Исправление

В существующем `cpu_retrack/identity_turnover.rs` разрешены два новых устойчивых трека при трёх исчезнувших. Остальные ограничения сохранены: длительные наблюдаемые треки, компактная непересекающаяся граница, минимум один продолжающийся трек, достаточный контекст с обеих сторон. Версия политики — `measured_roster_turnover_handoff_v3`. Это эвристика смены состава, не универсальный детектор видеосклеек.

## Продолжение: две рамки Влада на 00:32.3

На кадре 969 в версии `aefb50dd9fdb4a83ab907480b81403ad` оставались ID 10 и 15: оба описывали Влада, оба были интерполированы. ID 10 дорисовывался между кадрами 960 и 1030; сдвинутые рамки не проходили строгий порог подавления синтетических дублей.

Причина найдена в самом `volley-core/src/tracker.rs`: итоговый pose-score через `max()` обходил штраф за давность наблюдения. На кадре 940 трек с последним измерением на 850 получал преимущество над текущим треком с измерением на 935. После перехвата оба ID чередовались на одном теле, создавая независимые интерполяции.

Добавлен временной штраф `0.18 * freshness` в pose-ветку оценки. Возможность возврата после трёх секунд сохранена; изменена конкуренция устаревшей и текущей поз. Версия ассоциации `pose_coco17_recency_v2` используется и в manifest, и при проверке повторного использования CPU-результатов.

Регрессия на сохранённых координатах `volley-core/tests/fixtures/alternating_setter_tracks.json` сначала воспроизвела перехват (6 вместо 10 на кадре 940), затем сохранила ID 10 на всех измерениях 940–965. Все 33 теста трекера и 10 тестов конвейера прошли. Полный workspace с `--no-fail-fast`: volley-app 303 passed / 13 failed / 7 ignored (тот же список выше), остальные targets прошли: 220 core unit, 2 core integration, 22 inference / 4 ignored, 24 media unit, 7 media integration, 9 web. Fmt/check, WASM, ownership/roadmap и diff-check прошли.

Replay `94e8b347c4e54bfd9e9ff31d191d8d73`, SHA `2fe1bcf483abb66552c9e879267334fd344f25ef53650c857aab1c90fc387916`, rally `389e798fe39b4d9ba981e5a77c5bdf91`. На всех 120 кадрах 930–1049 проверено ровно одно тело в области Влада; на кадре 969 один ID 10 вместо двух. Контакт 940 — `overhead_pass`, ID 10. Дальний правый игрок ID 14 → Ирек.

Фотоавтопривязка ID 10 после стабилизации неоднозначна: Рузиля 0.80016, Влад 0.78789. Через штатный version-checked API сохранено уже данное пользователем подтверждение ID 10 → Влад, источник `manual`; обучение и альбом фотографий не менялись. Автоматическая идентификация остальных треков всего видео по-прежнему неполная. Это не оценка качества на независимом размеченном матче; GPU model tests и новый экспорт не выполнялись. Для просмотра требуется обновить вкладку и выбрать новую CPU-версию; автоматизация браузера ранее остановлена из-за невозможности достоверно определить URL окна.
