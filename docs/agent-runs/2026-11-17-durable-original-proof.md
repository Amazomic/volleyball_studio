# Повторная загрузка CPU-анализа: постоянная проверка оригинального видео

## Изменение

- В `rust/volley-media/src/preparation.rs` добавлено сохранение доказательства SHA-256 исходника в `<isolated-data-root>/verified-original-sources-v1/`. Квитанция привязана к каноническому пути, размеру, точному времени изменения и системному идентификатору изменения файла (USN/ctime+inode). Квитанции записываются атомарно, вне исходных видео.
- При совпадении идентичности файла сохраняется исходная проверенная запись SHA и метаданных без повторного потокового чтения видео. На ФС без надёжного change stamp выполняется прежняя полная проверка. Некорректные и устаревшие квитанции отвергаются.
- Повторные запросы к одному файлу сериализуются, чтобы при первом открытии параллельные вкладки не пересчитывали SHA независимо.
- В `rust/volley-app/src/preparation.rs` проверка с постоянной квитанцией подключена к авторитетному плану подготовки; инстансы без записи сохраняют прежний режим. Исходные видео, результаты GPU/CPU и пользовательские данные не изменяются.
- В `rust/volley-app/src/native_rally_preview.rs` убрана дублирующая проверка происхождения файла.
- Для старых анализов **первая** проверка полного SHA всё ещё нужна для создания доверенной квитанции, после чего последующие запуски используют быстрый путь.

У старого процесса 17 потоков `tokio-rt-worker` в непрерываемом ожидании WSL `p9_cli` (DrvFs/9P). Никакого принудительного завершения или изменения пользовательских задач не выполнялось. Проверка холодной загрузки после перезапуска не проведена.

## Ограничения

Квитанции — производный кеш, а не источник правды. Публичная проверка source proof и содержимое исходных CPU/GPU артефактов неизменны. На непроверенных файловых системах полная SHA-проверка не пропускается. GPU-инференс и качество детекции этой правкой не затронуты.
