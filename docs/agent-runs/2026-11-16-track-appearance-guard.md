# Проверка внешности перед объединением Track ID — 2026-11-16

База: `bc3b40ad8be236f5c168103e4ada5ecaed9da1ef`. Ветка: `codex/20261116/track-appearance-guard`. Изолированный рабочий каталог — `.studio-runtime/worktrees/track-appearance-guard`.

## Поведение

- `rust/volley-app/src/cpu_retrack/track_merge.rs`: геометрия оставлена только для отбора кандидатов; решение об объединении теперь проходит отдельный photo-ReID gate.
- `rust/volley-app/src/cpu_retrack/track_appearance.rs`: до назначения имён сравниваются до пяти разнесённых по кадрам реальных видеокропов на каждый Track ID через существующую native OpenVINO-модель person-reidentification-retail-0287. Требуется минимум три декодированных кадра на ID, строгое согласие внутри обоих треков и между ними. Косинусное сходство не является калиброванной вероятностью.
- Нет модели, видеокадров, достаточных фото либо согласованного визуального подтверждения — **никакого объединения**. При отсутствии геометрических кандидатов модель не запускается. Векторные данные не сохраняются и не используются как реальная личность спортсмена.
- `rust/volley-app/src/cpu_retrack.rs`: источник изображения — уже верифицированное подготовленное видео, только в новом, ещё не опубликованном CPU replay. Существующие GPU/CPU версии не изменяются.

## Регрессия и ограничения

- Тесты моделируют несколько фото одного человека, смешанный ID (первый игрок → другой игрок), недостаточное число фото, разнесённость кадров; проверяется отказ объединять без доказательств.
- Ранее сохранённый реальный CPU replay `d6451abac405`: `duplicate_track_ids_merged=0`. Кадр 940 / 31.33с: Touch Track ID 6, автоматическое имя Ирек; рядом тот же человек в других кадрах имеет Track ID 10 / Влад. На кадре 1045 оба Track ID действительно одновременно присутствуют. Это **не результат финального track_merge**, а ошибка upstream непрерывности/повторного использования ID. Текущий photo gate предотвращает новые ошибочные объединения, **но сам по себе не меняет старую подпись**.
- ReID фото в окне около 31с неоднозначно: медианное косинусное сходство ID6 в подозрительном окне с фотографиями ID10 ~0.377 против ~0.179 со старыми кадрами ID6. Это относительное наблюдение, не калиброванная уверенность. Без независимой локальной проверки нельзя переименовать/переприсвоить ID.
- Исследовано и снято экспериментальное разбиение длинного ID на глобальной границе состава: real replay не дал достаточного внутреннего согласия и такого утверждения нельзя делать. Нужна отдельная локальная проверка подэпизода, а не глобальный split.
