# Настройки вкладки «Анализ»: подсказки и влияние на обработку

Дата: 2026-11-18. База: `cfce40a`. Ветка: `codex/20261118/analysis-settings-tooltips`.

## Проверенный путь

`rust/volley-app/static/studio.html` → `studio_tabs.js::gpuProfile/postProfile` → `studio_pipeline.rs` → `inference_full` (GPU), `cpu_retrack` (Track ID), `cpu_touches` (PoseMotion) и `cpu_rallies` (розыгрыши). Результаты сохранены по профилям и ревизиям.

## Что исправлено

- Для всех 36 названий полей анализа добавлены подробные всплывающие подсказки на русском и английском, работающие при наведении и клавиатурном фокусе. Описания доступны скринридерам и переключаются по выбранной языковой настройке WASM. Подписи стали отчётливее и корректно переносятся.
- Удалён переключатель «Учитывать кисти, локти и плечи RTMPose», который не влиял на единственный новый алгоритм `PoseMotion` (тот и так запрашивал суставы). Новые запросы всегда передают `pose_classification=true`.
- Минимальная уверенность нового ID в интерфейсе теперь **0,28**, что соответствует фактическому порогу запуска нового трека ByteTrack. Низкоуверенные 0,10–0,28 могут лишь продлевать существующие ID.
- Порог сопоставления ByteTrack **начал управлять IoU** между измеренной и предсказанной рамкой; исходное значение 0,43 сохраняет прежние геометрические пороги. Порог неоднозначности теперь **отклоняет спорную привязку** вместо простого подсчёта; спорная детекция не создаёт новый призрачный ID. Тесты подтверждают изменение принятых Track ID и отсутствие ложных новых ID.
- Порог уверенности физического касания теперь применяется ко всем событиям PoseMotion, включая новые RTMPose-кандидаты, перед сохранением CPU-событий. Раньше новые RTMPose-кандидаты обходили этот фильтр. Регрессия подтверждает изменение событий при настройках 0,48 / 0,80 / 0,99.
- Параметр `smooth` включён в действующий `PoseMotion`: размер окна истинных VBallNet измерений для оценки скоростей мяча; его минимально допустимый размер UI — 2, по умолчанию 5.
- Диапазон `max_gap_frames` в UI — 1–180 (параметр ранее не позволял уменьшать значение меньше 90); `max_without_touch_frames` — 90–900, соответствуют Rust-валидаторам.
- Версии CPU-данных повышены: `bytetrack_xyah_two_stage_v2` и `vballnet_trajectory_body_contact_v12`. Перепривязка параметров не подменяется старым совместимым кэшем; исходный GPU остаётся неизменным.
- Тест `scripts/ci/test_studio_analysis_setting_effects.mjs` проверяет 36 названий, 33 значимых GPU/CPU элемента, передачу каждого в Rust-профиль и двуязычное доступное описание. Дополнительные Rust-тесты удостоверяют физическую семантику порогов и сглаживания.

## Границы и прозрачность

- «Потоки CPU» и «Лимит VRAM» влияют на ресурсы/скорость/запуск, а не обязаны менять численные детекции. Подсказки говорят об этом прямо.
- «Начало/конец, сек» принадлежат редактору исходного видео: сохранённая обрезка сейчас **не ограничивает кадры GPU-анализа**. Нельзя выдавать её за действующий фильтр GPU. Подсказки явно предупреждают об области действия.
- Интерполяция поз и контекст розыгрыша могут изменить предпросмотр/доступный контекст, а не оригинальные измерения нейросети.
- Качество касаний и ID на реальном размеченном матче пока **NOT MEASURED**: юнит- и интеграционные тесты подтверждают работу параметров, не превосходство по IDF1/F1. Новые CPU-настройки требуют нового CPU-пересчёта, но не повторного GPU.
