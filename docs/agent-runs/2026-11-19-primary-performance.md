# 2026-11-19 · Производительность первичного GPU-анализа

- База: `origin/develop` `fab5fa93d955c08db9e9c37e4966e9c90b03e4fa`; отдельный worktree `perf/20261119-primary-batching-preview`. Основная рабочая копия с незакоммиченными изменениями не затронута.
- Вход RF-DETR Medium (`models/rf-detr-medium.onnx`, SHA-256 `18250b5a...`) фиксирован: `[1,3,576,576]`. Замена только внешней размерности на `batch` приводит к ошибке broadcast ViT position embeddings. Оригинальная модель не изменялась.
- Исследован временный ONNX-граф из трёх ветвей с общими весами и тремя кадрами на один вызов ORT. Результаты на CPU и CUDA совпадают с тремя последовательными вызовами точно (`max_abs_diff=0` для двух выходов).
- Эксперимент CUDA, RTX 5070 Ti Laptop, Python ORT CUDA EP, три одинаково подготовленных по форме различных тензора, 3 прогрева и 7 прогонов: медиана трёх обычных вызовов 32,5 мс, одно обращение к экспериментальному графу — 34,2 мс. На этих данных ускорения нет, значит пакетный граф **не включён в продукт**. Это измерение модельного вызова, не FPS полного матча; реальные матчи и память не профилировались. Рекомендуемая дальнейшая работа — проверенный реэкспорт RF-DETR с нативным batch, а не дублированный граф.
- Кодирование браузерного предпросмотра убрано из синхронного общего FFmpeg-декодера. После завершения GPU-инференса запускается самостоятельная фоновая задача FFmpeg; её завершения не ждёт GPU/CPU-конвейер. Сохраняются native FPS/PTS, первый аудиопоток, atomic publish, привязка к SHA исходного файла и существующий формат кэша. При отказе NVENC используется libx264.
- В каждый момент времени кодируется только один предпросмотр для данной пары проект/видео; `shutdown_safe` учитывает активную операцию, чтобы не обрывать FFmpeg при перезапуске. В отсутствие готового предпросмотра существующий API отдаёт состояние `missing` и сохраняет прежний путь fallback-проигрывания.
- Владельцы: `rust/volley-app/src/inference_full/joint.rs`, `studio_pipeline.rs`, `preparation/primary_preview.rs`, `runtime.rs`; `rust/volley-media/src/preparation/primary_preview.rs`.
- Ограничения: для отдельного предпросмотра требуется второй проход декодирования исходного видео; он выполняется после GPU-анализа и не блокирует его, но потребляет диск/CPU/NVENC. Внешнее изменение оригинала после GPU-этапа не публикует несогласованный preview. Реальный GPU-анализ матча и до/после полного wall-time — NOT TESTED.
