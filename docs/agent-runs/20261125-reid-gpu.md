# 2026-11-25: GPU batch ReID

Base: 3043f775659f963d449579d11c42a036c21da2ea. Windows-native HOME-PC, RTX 5070 Ti Laptop, Ryzen 9 9955HX and Radeon 610M. Scope: ReID encoder and its four native call sites. No changes to video decoding/crop/resizing, tracking, pose, Touch, ground, rally or scoring logic.

## Model provenance and selection

The checked-in ONNX is derived from the existing bundled retail-0287 IR (no new trained weights). Development conversion in an isolated Python tool directory: OpenVINO 2025.4.0, openvino2onnx 1.1.0, onnx 1.17.0. Read the original IR, reshape the sole input to [16,3,256,128] using OpenVINO Model.reshape, save with compress_to_fp16=False, then run python -m openvino2onnx batch16.xml batch16.onnx -v 19. No Python runtime dependency in Studio.

- Original BIN SHA-256: 5a6f414c9ef2b9034f821a0cab31f4416de777f777709806e5ef3ff6d7d5af3a
- ONNX SHA-256: 13b2e60ffe4320bcc97a820c642c9fe3b304291631544b4df883d13b66945807
- Input: raw BGR FP32 NCHW, unchanged 128x256 crop and 0..255 values. Output: 256 L2-normalized values per image.
- Only the pinned original IR + FP32 inference contract may select the pinned CUDA model. A process-local serialized session is initialized lazily; 8-16 new images use CUDA, smaller chunks use OpenVINO CPU. The last CUDA chunk is padded; padded outputs are never published. Strict CUDA provider registration and no internal CPU operator fallback. GPU arena limit 512 MiB, TF32 disabled. GPU startup or inference failure is logged and uses the existing CPU encoder, not an invented descriptor. Set VOLLEY_REID_DEVICE=cpu for an A/B CPU-only run before launch. A failed first CUDA session initialization is cached until process restart.
- Native OpenVINO previously chose BF16 on this CPU. GPU/CPU now both request FP32. The inference contract is included in model fingerprint 91a71dd9f0334cd98d5db2922b4bd80a6d0a3d45911de38ed0c541e9520782de; crop preprocessing schema is unchanged. Existing transient ReID caches/automatic assignments with a different model fingerprint become stale and are regenerated through normal checked cache paths, never mixed. Confirmed manual identity assignments, reference images and immutable inference evidence are not changed by this migration.

## Measurements

Isolated synthetic tensors/crops, no user projects. OpenVINO direct GPU failed compiling the IR on NVIDIA. Single-image CUDA ONNX was slower (14.11 ms vs 3.42 ms for FP32 CPU). Python proof-of-concept batch 6: 2.66 vs 1.08 ms/image; batch 16: 2.55 vs 0.55 ms/image; these used FP32 CPU. Native Rust release test initially failed against automatic BF16 (cosine 0.999768; separate patterned batch max pairwise cosine drift 0.009467). After selecting FP32 on both backends, native tests pass the original thresholds: corresponding cosine > 0.9999, pairwise cosine drift < 0.001; padded and mixed 16+1 ordering verified. Native warm batch16: CPU 2.266 vs CUDA 0.718 ms/image; repeat 2.232 vs 1.311 ms/image. Native warm padded batch8: 1.359 ms/image. These are warm encoder timings, not full analysis speed or independent match identity quality.

Synthetic H.264 4K, software vs CUDA vs D3D11 crop extraction, first 6 crops: 523.6/465.1/417.3 ms median, byte-identical outputs. Repeat 3 crops with explicit AMD/CUDA hardware decode: CPU 185.3 ms, AMD 607.2 ms, explicit AMD 394.6 ms, explicit CUDA 292.1 ms; all three pixel checks match. No stable gain, so no decode/crop/scale backend change. GPU-resident crop/scale parity not certified.

Native release command: set VOLLEY_TEST_REID_CUDA=1, VOLLEY_TEST_OPENVINO_C_LIB to the native OpenVINO C DLL, ORT_DYLIB_PATH to the native CUDA ORT DLL, add their native dependency directories to PATH, then from rust run cargo test -p volley-inference --release --locked --offline reid_openvino -- --nocapture. Six tests passed. No real-match identity quality, concurrent RF-DETR/RTMPose load or end-to-end full-analysis acceleration measured.
