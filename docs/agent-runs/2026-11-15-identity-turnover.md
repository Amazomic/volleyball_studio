# 2026-11-15 · Межрозыгрышная смена личности Track ID

## Воспроизведение

На текущем коротком видео проекта `d6451abac405` (1737 кадров, 30 FPS), после CPU replay `cc8407c3f77141e9aff715631ad23438`, на 00:11.3:
- ID 4 — Ирек, 83.3% по фото, не назначен.
- ID 5 автоматически закреплён за Иреком (85.3%), хотя в первом розыгрыше этот Track ID у Раили, а во втором — у Ирека.
- Измеренные интервалы: ID 4 = 0..850, ID 5 = 0..1730. В районе 849..860 сразу несколько ID исчезают и несколько появляются, но ID 5 сохраняется. Общая привязка `Track ID → игрок` поэтому смешивает два разных человека.
- Прочитаны только метаданные и позиции измеренных треков; фото, исходники, старые replay и привязки пользователя не менялись.

## Исправление

Модуль `rust/volley-app/src/cpu_retrack/identity_turnover.rs` проверяет по **реальным** наблюдениям массовую смену треков: минимум три достаточно длинных трека заканчиваются, три начинаются в узком окне, между группами нет пересечения и при этом есть ID, проходящий через обе фазы. Такой сквозной ID разделяется на два непересекающихся ID при публикации нового CPU replay. Новые ID назначаются детерминированно, исходные детекции и SHA-контроль сохраняются. Интерполяция выполняется уже после разделения, без склейки разных людей.

В `rust/volley-app/src/cpu_retrack.rs` включена стадия и добавлены поля происхождения `identity_turnover_version` и `identity_turnover_splits` в манифест. На реальном индексном наборе проверяется разделение ID 5 около кадра 856 (≈28.5с); после новой постобработки ID 4 и новый ID для второго розыгрыша могут независимо сопоставляться с Иреком, а прежний ID 5 — с Раилей.

Не выполнено ретроактивное изменение старых анализов: старые CPU-версии неизменяемые. Для видимого результата необходим запуск новой CPU-постобработки и последующей автопривязки. GPU-инференс повторять не требуется.
