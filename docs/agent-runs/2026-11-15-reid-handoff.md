# 2026-11-15 · ID 13 переключился на Ильнура внутри второго розыгрыша

## Диагноз по реальному сохранённому CPU replay
- В коротком проекте `d6451abac405` на 00:31.0 (frame 930) **измерены одновременно два разных человека**, Track ID 12 и Track ID 13; это подтверждено сохранёнными bbox, не синтетическими интерполяциями.
- На ~00:34.8 (frame 1044) у Track ID 13 зафиксирована скачкообразная смена bbox: от ~[0.4296,0.4249,0.4622,0.5683] на ~[0.4429,0.4528,0.4793,0.6537]. Новый bbox хорошо совпадает с **измеренным** ID 12 на frame 1041 ([0.4435,0.4749,0.4876,0.6601]), а не с прежним ID 13. ID 12 исчезает с кадра после 1053; ID 13 виден на 46.3с и далее.
- Фото-ReID прежней версии: ID 12 = Ильнур, 85,5%; ID 13 = Ильнур, 78,3%. Система корректно запрещала назначить владельца **целого** Track ID 13, так как его ранние измерения принадлежат другому человеку и пересекаются с ID 12.
- Во время диагностики пользовательский источник CPU `4c8e5a4ad9ae458a92b6cfaf94c7bf4b` был заменён/удалён извне; старые данные пользователю не восстанавливались и не переписывались. Геометрия и временные признаки были извлечены до исчезновения. Новый CPU анализ можно сделать по выбранному сохранённому GPU источнику.

## Исправление
- Добавлен детектор `rust/volley-app/src/cpu_retrack/identity_handoff.rs`: обнаруживает передачу Track ID на чужое тело только при многократно подтверждённом **реальном** совместном наблюдении двух разных тел, скачке bbox на место другого недавно измеренного тела, достаточном числе измерений по обе стороны и без привлечения интерполяции.
- `rust/volley-app/src/cpu_retrack/identity_turnover.rs` выполняет split верифицированного потока до интерполяции: раннюю чужую часть ID 13 получает новый Track ID; **поздняя часть сохраняет ID 13**. В ином месте видео ID 12 не препятствует назначить владельца новому самостоятельному позднему треку ID 13.
- `rust/volley-app/src/cpu_retrack.rs` отмечает `identity_turnover_version=measured_roster_turnover_handoff_v2`, отдельное `identity_handoff_splits` и пересчитывает количество подтверждённых Track ID. Исходные GPU detections, видео, позы и прежние immutable CPU snapshots не модифицируются.
- Условия ручной привязки уже проверяют измеренные bbox на **одном и том же кадре** через `measured_conflict_frame`; менять это на совпадение временных диапазонов было бы ошибкой. После правильного split ложное пересечение исчезает. Аналогично auto-ReID оценивает отдельно каждую часть.
