# Дообучение: сравнение розыгрышей по траектории и ручной эталон

## Поток данных и границы ответственности

1. Первичный GPU-анализ сохраняет наблюдения мяча VBallNet и игроков/RTMPose.
2. CPU replay `native_cpu_replays/<replay_id>/tracked_frames.jsonl` хранит выбранный мяч с SHA-256.
3. Детектор `cpu_retrack/ball_track.rs::preliminary_rally_scope` находит перегибы «вниз → вверх» **только по мячу**, независимо от назначения игроку/типа удара. CPU Touch записывает `native_cpu_touch_runs/<touch_id>/preliminary_rallies.json` с `trajectory_impacts`, `rally_intervals`, параметрами и контрольной суммой в манифесте.
4. Основная CPU-постобработка использует предварительные границы для ограничения анализа и отдельно формирует подтверждённые позой/движением кандидаты касаний и временную разметку розыгрышей. Исходные GPU/CPU снимки неизменяемы.
5. Вкладки «Просмотр» и «Дообучение» используют один выбранный `project_id + rally_run_id + video` и один временной ряд. API `GET /api/training/rally-comparison` через `inspect_project` проверяет цепочку CPU/Touch и SHA-256 сохранённых перегибов, затем в памяти пересчитывает интервалы по выбранным параметрам; CPU-версию не перезаписывает.
6. `GET/POST /api/training/annotations` работает с самостоятельным эталоном. Сохранённые исправления не становятся предсказаниями детектора. `reviewed=true` разрешает вывод метрик против эталона; черновик не считается проверенной точностью.

В старой CPU-версии без `preliminary_rallies.json` кнопка моделирования запускает **read-only** пересчёт перегибов из сохранённого `native_cpu_replays/<replay_id>/tracked_frames.jsonl` после проверки SHA-256. Повторный GPU-анализ и пересоздание CPU-версии не нужны; результаты не записываются поверх оригинала.

## Работа во вкладке «Дообучение»

Выберите проект, видео и сохранённую CPU-постобработку. Сверху показаны количество розыгрышей обоих способов, однозначные совпадения при IoU ≥ 0,5, пропуски/лишние интервалы и F1. Измените число перегибов (1–10), запас до/после (0–180 кадров), минимальную длину (15–900 кадров), максимальную паузу между перегибами (90–120 кадров), затем нажмите **«Смоделировать розыгрыши и касания»** над видео. Кнопка выводит интервалы и кандидаты касаний из сохранённой траектории с выбранными параметрами; они не равны подтверждённым действиям игрока. Применение параметров только экспериментальное и не меняет CPU-анализ.

На **единой** шкале под видео: CPU-розыгрыши — синеватые, интервалы по мячу — оранжевые, эталонные метки — зелёные, точки перегибов — светло-оранжевые, смоделированные кандидаты касаний после нажатия кнопки — ярко-жёлтые. Фильтр «Проверка расхождений» показывает пропущенные обоими способами кандидаты, несогласные границы и совпадения. Нажатие на элемент переводит исходное видео к спорному эпизоду.

Редактирование выполняется кликом по метке общей шкалы или по видео на паузе. Открывается меню добавления, сдвига/удаления касания и изменения границ розыгрыша. Теперь правки остаются локальным черновиком и не сохраняются автоматически: нажмите «Сохранить данные касаний», чтобы записать их атомарно с проверкой ревизии. После сохранения повторно нажмите «Рассчитать касания по мячу», чтобы подобрать порог/сдвиг на сохранённых примерах. Отдельное «Завершить проверку видео» подтверждает эталон. Прежние сохранённые метки не удаляются.

## Две цели сохранённых данных

- `<data_root>/training/touch_annotations.json` — версия 1 эталона: кадры касаний, начала/концы розыгрышей, ревизии, источник и подтверждение. Используется для проверки кастомного детектора касаний/розыгрышей и как размеченный источник данных для будущего обучения TCN.
- `<data_root>/training/examples.json` — версия 1 библиотеки RTMPose: подтверждённые человеческие касания, точки тела, признаки движения и разметка площадки. Эта библиотека влияет на **следующий CPU-анализ** алгоритма, а не заменяет эталонные временные метки.
- `preliminary_rallies.json` — независимые предварительные интервалы и перегибы мяча, вычисленные до ручного подтверждения. При изменении порогов расчёт выполняется из сохранённых перегибов без запуска GPU.

Текущие веса Volley3D TCN **не дообучаются** по кнопке сохранения и вкладка не утверждает, что модель переобучена. Для реального обучения потребуется отдельный версионированный датасет последовательностей VBallNet с ручными метками, делением по исходным видео на train/validation/test и отдельным запуском тренировки. F1 сравнения CPU с детектором мяча не является независимой оценкой качества: предварительная траектория уже участвует в CPU-пайплайне; ориентир качества — сравнение с подтверждённым ручным эталоном.

## Реализация

- `rust/volley-app/src/rally_training_comparison.rs` — HTTP сравнение, проверка источника и детектор одних и тех же сохранённых перегибов
- `rust/volley-app/src/touch_annotation.rs` — эталон и метрики подтверждения
- `rust/volley-app/src/training_samples.rs` — отдельная библиотека RTMPose
- `rust/volley-app/static/studio.{html,js,css}` — редактор, сравнение и общая шкала
- `scripts/ci/test_training_rally_comparison.mjs` — UI/источники/навигация расхождений и моделирование
- `scripts/ci/test_training_context_actions.mjs` — действия контекстного меню по клику и защита от непреднамеренной разметки


## Калибровка касаний по траектории VBallNet — перенос старой ветки

В режиме «Дообучение» работают два отдельных расчёта. «Смоделировать розыгрыши и касания» использует существующее сравнение CPU-разметки и интервалов мяча. Новая кнопка «Рассчитать касания по мячу» запускает POST /api/training/trajectory/calculate: по всей записи ищет scored-кандидаты перегибов из сохранённого CPU replay, проверяя SHA-256, и не запускает GPU/RTMPose повторно.

Рабочий цикл:
1. Выберите проект, видео и CPU-постобработку. Нажмите «Рассчитать касания по мячу». На единой шкале под видео появятся жёлтые прогнозные маркеры, не являющиеся подтверждёнными касаниями.
2. «Взять расчёт для правок» переносит прогноз в локальный черновик с зелёными маркерами. Также можно использовать CPU-метки в качестве основы. Маркеры и границы розыгрышей исправляются кликом по видео, перетаскиванием, удалением и смещением по кадрам. Переключатель метода включает траекторию VBallNet или точки RTMPose; фильтр скрывает лишние слои.
3. Пока черновик изменён, повторный расчёт блокирован. «Сохранить данные касаний» выполняет POST /api/training/annotations с action=save, revision, UUID, touches и rallies. Rust проверяет исходник, CPU-версию, уникальность и диапазоны кадров и сохраняет в training/touch_annotations.json независимо от CPU/GPU evidence. Одновременно кеширует признаки scored-кандидатов и SHA CPU replay.
4. Повторное нажатие «Рассчитать касания по мячу» подбирает порог score и сдвиг −2…+2 кадра по сохранённым примерам, в том числе по отрицательным примерам без касаний. Отображаемая точность — только на обучающих видео, не независимая валидация. Уже подтверждённые разметки из прежней версии без нового кеша автоматически участвуют в калибровке текущего видео через временно вычисленные scored-кандидаты. Этот путь ничего не сохраняет и не снимает статус подтверждения; явное сохранение новых правок по-прежнему обязательно.
5. «Завершить проверку видео» подтверждает сохранённый эталон отдельно от сохранения черновика. Веса TCN/RTMPose при этих действиях не обновляются; GPU и исходные CPU-результаты не перезаписываются.

Канонический motion-детектор: rust/volley-core/src/motion/trajectory.rs. Полный SHA-проверяемый scan: rust/volley-app/src/native_player_tracks/trajectory.rs. Подбор профиля и read-only API: rust/volley-app/src/touch_annotation/trajectory.rs. Сохранение: rust/volley-app/src/touch_annotation.rs. UI: rust/volley-app/static/studio.js, studio.html, studio.css. Сравнение временных границ розыгрышей остаётся в rust/volley-app/src/rally_training_comparison.rs.

Проверки включают синтетический полный replay с неверным SHA, совместимость старой JSON-схемы меток, калибровку порога/сдвига на позитивном и негативном примерах и интерактивный Node-тест цепочки Calculate → Adopt → Edit → Save → Recalculate. Реальные видео, точность на независимом матче и GPU требуют отдельной проверки.
