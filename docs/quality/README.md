# Проверка качества анализа и монтажа

В репозитории нет публичного полного датасета с независимой разметкой матчей. Синтетические тесты проверяют математику и контракты, а не точность модели на реальном видео. Если измерения нет, результат — NOT MEASURED, а не нулевая ошибка.

## Доступный инструментарий

[benchmark_rust_parity_84.mjs](../../scripts/ci/benchmark_rust_parity_84.mjs) — строгий оценщик Python/Rust на одном исходнике с независимой человеческой разметкой. Он считает Touch precision/recall/F1 с допуском 0,15 с, границы розыгрышей через IoU и глобальный IDF1 по рамкам. Для приёмки он также требует сопоставимые настройки, происхождение результатов, измерения ресурсов и внешние проверки.

Проверка математики оценщика без реального матча:

~~~sh
node scripts/ci/test_rust_parity_84.mjs
~~~

Результат этого теста не является измерением точности Studio.

Команда для подготовленного реального набора свидетельств:

~~~sh
node scripts/ci/benchmark_rust_parity_84.mjs --evidence /private/parity-evidence.json --source /private/exact-source.mp4 --out /private/parity-report.json
~~~

В evidence требуется существующая схема volley-parity-evidence/1: asset с SHA/FPS/исходным диапазоном, truth с kind=human_independent, разметкой touches/rallies/tracks и её SHA, runs.python/runs.rust с фактическими результатами, профилями и телеметрией, external со свидетельствами проверок. Точный контракт задают evaluate() и его тесты в ссылках выше. Отдельные упрощённые before.json/after.json не являются входом этой команды.

Ненулевой код означает ошибку или NO-GO; читай reasons, не ослабляй требования для зелёного результата. Исторические [свидетельства](../RUST_BENCHMARK_84_EVIDENCE.json) содержат truth=null и недоступные прогоны: их нельзя выдавать за пригодную независимую разметку. [Отчёт этапа 84](../RUST_BENCHMARK_84.md) — датированный исторический результат, а не диагноз текущего окружения.

## Новое сравнение Rust/Rust

Универсального актуального CLI quality_eval.py в этой ветке нет. Прежние Python-команды и схема volley-quality-annotations/1 не являются поддерживаемым измерителем. Оценщик этапа 84 предназначен для Python/Rust: не подменяй одну сторону Rust-прогоном, чтобы объявить приёмку.

Для конкретного улучшения сначала определи сопоставимые Rust-версии, один исходник и диапазон, независимую разметку, версии моделей, параметры и список метрик. Можно повторно использовать пригодные математические функции оценщика, но отдельный воспроизводимый Rust/Rust-отчёт и недостающие метрики требуют явно описанного контракта. До его реализации отмечай пробел и не заявляй полный бенчмарк.

Разметка хранится вне публичного Git без персональных фото и имён. Нужны реальные касания, границы розыгрышей и, для проверки идентичности, независимые покадровые связи людей с рамками. Выход модели не используется как эталон самого себя.

## Изменение CPU-настроек

Действующие значения и схемы находятся в Rust: GpuProfile/PostProfile в [studio_pipeline.rs](../../rust/volley-app/src/studio_pipeline.rs), TrackingOptions в [tracker.rs](../../rust/volley-core/src/tracker.rs), TouchSettings в [touch_pipeline.rs](../../rust/volley-core/src/touch_pipeline.rs), RallySettings в [rally_reconstruction.rs](../../rust/volley-core/src/rally_reconstruction.rs). Для конкретного запуска проверяй сохранённый профиль, а не только defaults в коде.

Удалённый scripts/volleyball_ui/static/cpu-defaults.json не управляет Rust Studio; старые ревизии описывают исторический Python-профиль. Изменение CPU-интерпретации использует сохранённые GPU evidence, когда наблюдений достаточно, и создаёт отдельную версию без перезаписи исходных данных.

При оценке сравнивать одинаковые размеченные эпизоды до/после: ошибки касаний, ID switches/ложные объединения, границы розыгрышей и попадание нужного спортсмена в монтаж. Совпадение общего числа касаний не доказывает правильность каждого контакта. Для типов действий и монтажа фиксировать отдельно неизвестные/непроверенные показатели.

Полная матрица требований: [AGENT_IMPROVEMENT_CHECKLIST.md](../AGENT_IMPROVEMENT_CHECKLIST.md). Локальные регрессии: [TESTING.md](../TESTING.md). Просмотр итогового видео дополняет численные проверки, особенно при окклюзиях, смене ID и полёте мяча рядом с игроком без контакта.
